# Ergene Basin 2013 Dataset

## Source

Arkoc, O. (2014). *Heavy Metal Concentrations of Groundwater in the East of Ergene Basin, Turkey.*
Bulletin of Environmental Contamination and Toxicology, 93:429-433.
DOI: 10.1007/s00128-014-1347-x

## File and scope

- File: `data/ergene-2013-measurements.json`
- 108 records: 18 wells x 6 metals
- Medium: `groundwater`
- Unit: `mg/L`
- Source: `literature`

This data represents groundwater wells in the Ergene Basin, not the river itself.
The dashboard should not merge these records into a single time series with the 2025 and 2021 river water records. Water medium and sediment data must also not be merged into the same series.

## Data rules

- Records with `value: null` and `below_detection_limit: true` are BDL (Below Detection Limit); they are not zero.
- BDL records are excluded from risk threshold comparisons.
- Since the date in the 2013 records is given only as May 2013 in the article, it is represented with the assumption of `2013-05-15T10:00:00+03:00`.
- Coordinates were converted to decimal degrees from the PDF map; their accuracy should be evaluated within the limitations of the data source.
- `coordinate_source` might not be present in this dataset and is optional.
- Records may contain source metadata fields like `parameter_symbol`, `detection_limit`, `well_depth_m`, `ph`, and similar; the backend request DTO does not carry these over to the API response. The frontend should use the `/api/observations` response for listing.

## Threshold and risk

Only verified thresholds defined within `ThresholdConfig` are used for water samples. In the 2013 data, the chromium values in wells 9 and 13 specifically are examples that exceed water thresholds. Sediment rules are not applied for this dataset.

## Backend and FHIR behavior

The seeder idempotently loads this file via `ObservationService.create()`. If the same `measurement_id` exists in the database, the record is not added again.

The backend's current FHIR client sends the following fields for the `Observation` resource:

```json
{
  "resourceType": "Observation",
  "status": "final",
  "code": { "text": "chromium" },
  "valueQuantity": { "value": 0.1, "unit": "mg/L" }
}
```

LOINC code, subject, referenceRange, and interpretation are not fabricated. For BDL records, `valueQuantity` is not sent; the value field is left empty in the current MVP FHIR flow.

## Frontend usage

- All observations: `GET /api/observations`
- 2013 filter: `GET /api/observations?from=2013-01-01&to=2013-12-31`
- Location selection: `GET /api/locations`
- The location value is not generated by the frontend; the exact `location_name` coming from the API is sent back for `GET /api/risk-status?location=...`.
